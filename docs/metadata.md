# Equation metadata format (`lavatex-equation/1`)

A LavaTeX equation is an ordinary picture. What makes it editable is a small JSON record stored alongside the image, so that hosts and file formats that know nothing about LavaTeX still show the picture, and any LavaTeX host can recover the source.

## The record

```json
{
  "schema": "lavatex-equation/1",
  "source": "\\frac{a}{b}",
  "preamble": "\\usepackage{amsmath}\n\\usepackage{amssymb}",
  "mode": "display",
  "fontSize": 20.0,
  "color": "#000000",
  "format": "svg",
  "engine": "latex",
  "widthBp": 12.4,
  "heightBp": 21.7,
  "depthBp": 6.9,
  "generator": "LavaTeX 0.1.0"
}
```

| Field | Meaning |
|---|---|
| `schema` | Always `lavatex-equation/1`. Readers reject other values rather than guess. |
| `source` | LaTeX body as typed by the user. |
| `preamble` | Preamble lines used for this equation. **Untrusted** when the file came from someone else (see [security](../SECURITY.md)). |
| `mode` | `display` (`$\displaystyle …$`), `inline` (`$…$`) or `text` (raw LaTeX in a box). |
| `fontSize` | Points. Equations are typeset at 10 pt and scaled by `fontSize/10`. |
| `widthBp`, `heightBp`, `depthBp` | Rendered size in PostScript points (1/72 in) at `fontSize`; `depthBp` is below the baseline. Hosts use `widthBp` to keep the user's scale on edit. |

Readers ignore unknown fields, so new optional fields can be added without bumping the schema.

## Where it is stored

Writers store the record in every place below that the host supports. Readers try them in this order and use the first valid record.

1. **Host-native properties** (best inside the host):
   - LibreOffice: shape `UserDefinedAttributes`, key `lavatex:equation`, namespace `https://lavatex.org/ns/1`, value = record JSON. Persists in ODP.
2. **Alt text / description** (survives almost every format conversion). The human-readable source comes first, then a marker line:
   ```
   \frac{a}{b}

   lavatex:1:<base64url(record JSON), no padding>
   ```
   Readers take the **last** `lavatex:1:` marker and the base64url characters after it.
3. **Inside the image bytes** (survives copying the picture between apps):
   - **SVG**: `<metadata><lavatex:equation xmlns:lavatex="https://lavatex.org/ns/1" encoding="base64">…</lavatex:equation></metadata>` as the first child of the root `<svg>`.
   - **PDF**: document-info entry `/LavaTeX`, as a hex string or an escaped literal string containing the record JSON. Object streams are disabled so the entry is readable.
   - **PNG**: an uncompressed `iTXt` chunk with keyword `LavaTeX`, placed before `IEND`.

## Observed survival (LibreOffice 24.2, automated test)

| Inserted as | Saved as | Picture kept as | Layers that survive |
|---|---|---|---|
| SVG | ODP | SVG | attributes, alt text, image |
| SVG | PPTX | SVG (with PNG fallback) | alt text, image |
| PDF | ODP | PDF | attributes, alt text |
| PDF | PPTX | PNG | alt text |
| PNG | ODP | PNG | attributes, alt text |
| PNG | PPTX | PNG | alt text |

ONLYOFFICE's API cannot read image bytes back, so ONLYOFFICE relies on the alt text (`ApiDrawing.GetDescription`, ONLYOFFICE 10.0+).

## Size limits

Readers reject records over 256 KiB, and sources or preambles over 64 KiB are refused before rendering.

## Conformance

`fixtures/metadata/alt-text.json` is generated by the Rust core (`LAVATEX_UPDATE_FIXTURES=1 cargo test`). The JavaScript and Python readers are tested against it, so all three implementations agree byte for byte.
